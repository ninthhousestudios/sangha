## What to pick up next

### 1. Use it from real sessions

Open a fresh Claude Code session in any project — the `mcp__sangha__*` tools
will be available. To make a project actually call sangha, drop the CLAUDE.md
fragment from `docs/future-hooks.md` into that project's CLAUDE.md.

### 2. Wire skills to claim advisory locks

`/done` and `/reflect` should claim a lock on artifacts they write
(e.g. `docs/handoff.md`, `.handoffs/*`) before writing. Pattern:

1. `mcp__sangha__resource_claim` with `resource: "docs/handoff.md"`
2. If `ok: false`, abort with `held_by` info
3. On success, write the file
4. `mcp__sangha__resource_release`

### 3. Loose ends worth knowing

- **Connection lifecycle**: `Identity` is connection-bound. If a Claude Code
  session loses its HTTP keepalive and reconnects, it will get a fresh
  identity and need to call `session_register` again. Behaviour under
  reconnect hasn't been exercised in the wild yet.
- **CLI `sangha locks` (non-JSON) doesn't print branch.** The branch *is*
  populated in the DB now (M7 fix verified via `--json`); the text formatter
  in `cmd_locks` just doesn't print it. Trivial to add if useful.
- **Migrations are now idempotent** (`CREATE TABLE IF NOT EXISTS`) — the
  original DDL crashed when `sangha health` had pre-created the schema. Any
  future migration must keep this property or add real versioning.
- **`session_recreated` was removed** from `ClaimResult` / `ClaimOutput`. If
  you wire any external consumer to that field, it's gone.
